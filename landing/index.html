The workflow

Describe it. Ship it. Verify it.

Vibe coding falls apart when a styling prompt silently breaks a payment call. This codebase is arranged so the two can't touch — and so the agent can prove its own work before you look.

Prompt the surface

Ask for the change in plain language. Components are small, typed, and named for what a shopper sees.

The agent edits UI only

Markup, classes and theme tokens. Commerce calls stay behind the service barrel, so there is nothing to accidentally rewrite.

import { ProductService }
  from '$lib/core/services'
// ↑ never a backend name

Types close the loop

One command type-checks the whole app. The agent runs it, reads the errors, and fixes itself before handing back.

npm run check
✓ 0 errors
Why it survives editing

Five seams that keep agents in their lane.

None of this is AI-specific — it is just strict separation. It happens to be exactly what makes a codebase safe to hand to a model.

One import for all commerce

Every page reaches products, cart, checkout and auth through a single barrel. No component knows which platform is behind it, so UI work physically cannot reach the integration. 

import { CartService, ProductService }
  from '$lib/core/services'

The backend is one line

Swap Shopify for Vendure by changing an export and installing the matching connector. Every connector implements the same service surface, so the storefront is unchanged. 

// kitcommerce.config.ts
export * as services from '@misiki/vendure-connector'

Themes are data

Copy, imagery and section content live in the theme layer — not inline in routes. A redesign adds a theme instead of forking pages.

Typed end to end

TypeScript across routes, services and connectors gives an agent a real pass/fail signal instead of a guess.

Vocabulary models know

Svelte 5 runes, Tailwind utilities and shadcn primitives — conventions with enormous training coverage.

FAQ

Questions

What actually makes it agent-friendly?

Separation, not magic. Commerce is reachable only through $lib/core/services, so a styling edit has no path to checkout. Theme content lives in theme files rather than inline in routes. And npm run check type-checks everything, giving an agent a real pass/fail loop instead of a guess.

Do I have to migrate my products?

No. Svelte Commerce reads from your existing backend over its API. Products, orders and customers stay exactly where they are.

Can I use it with Shopify?

Yes, through @misiki/shopify-connector (16 of 27 services wired). You add the environment branch yourself — built-in wiring ships for Litekart, Vendure, Medusa and Saleor.

What if my platform isn't one of the 26?

Write a connector. It is a set of services extending a shared BaseService, matching the method signatures in the Litekart reference connector. Connector repos are standalone and independently buildable.

Is it really free for commercial use?

Yes — MIT licensed, checkout included. There is no open-core tier and no paid unlock.
