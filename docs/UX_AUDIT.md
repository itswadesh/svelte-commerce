# Svelte Commerce UX audit

Date: 2026-09-03. Scope: the storefront on the **default theme**.
Rulebook: [UX_SYSTEM.md](../UX_SYSTEM.md). Every finding names the rule it breaks.

The repository also ships wine, organic, lime and noor. Those are out of scope: this audit covers
what a shopper meets on the default theme, and findings that existed only in the other four have
been removed. Shared code is still in scope wherever the default theme renders it.

This audit is the "audit first" step that [UX_SYSTEM.md](../UX_SYSTEM.md) section 8 requires before
any redesign. Use it by picking finding ids into a page task, in the wording of section 9 of that
document. The design plan sequences the first five page tasks.

## Method

Sixteen agents audited one dimension each, reading the components and routes in full and
screenshotting the storefront at 360, 390, 768, 1024, 1280 and 1440 pixels wide.

Every finding was then challenged by a reviewer whose instruction was to refute it, working from
the cited code and, where the storefront could show it, from a browser reproduction. Findings rated
Critical or High went to a second, independent reviewer. Anything unproven was dropped rather than
softened. An editor per area then merged duplicates, removed anything specific to the other themes,
and levelled severity.

Evidence base: 139 findings reproduced in a browser, 43 confirmed by
two independent reviewers, 165 verified against the code alone.

The backend was a local GoCommerce store with three products, no product images, no accounts and no
server-side sort or filter parameters. Behaviour that catalogue cannot exercise was verified from
code, and is marked as such. A missing product image is treated as data, not as a defect, except
where the storefront itself handles the empty state badly.

## Findings

### Global navigation

The default theme's header loses its menu entirely at tablet width, ships no search control at all, and hands mobile shoppers a drawer that keyboard and screen-reader users cannot operate.

#### UX-010 · Mobile listing header replaces all navigation with a back chevron
- **Evidence** — `src/lib/components/nav/nav.svelte:209` "{#if navModule.isProductListingPage}"; `src/lib/components/nav/nav.svelte:211` "aria-label="Go back" onclick={navModule.goBack}"; `src/lib/components/nav/nav.svelte:225` "{(navModule.productsCount ?? 0).toLocaleString('en-US')} products"; screenshot `header-nav-r4-plp-390-crop.png`.
- **Impact** — A phone shopper who lands on a listing page from an ad, a shared link or a search result gets a header with no menu button, no brand link and no search. Pressing the only control there sends them to `about:blank`, off the storefront, and the row beneath it repeats the heading the page body already shows.
- **Fix** — Keep the persistent header on listing routes and leave the title and count to the listing page's own heading area, where they already exist. If a back affordance stays, make it a real link to the parent category or `/products` using the existing ghost icon button.
- **Rule** — 5 Permanent UX rules > Global navigation > "Preserve user context when returning from a product page to a list"; 10 Definition of done > "No new console errors or broken navigation". **Verified** — two reviewers.

#### UX-011 · Search is never rendered because the store flag ships false
- **Evidence** — `src/lib/components/nav/ms-search.svelte:60` "{#if searchPlugin?.active !== false}"; `src/lib/core/connectors/default-store.json:298` ""search": { "active": false, "placeholder": "Search ..." }"; `src/lib/core/connectors/static-store.ts:16`; `src/lib/components/nav/nav.svelte:250` "<MsSearch />"; `node_modules/@misiki/gocommerce-connector/dist/services/index.js:1441` "async searchAutoComplete(params = {})"; runtime check on `/` at 390px and 1280px returns zero elements matching `[aria-label="Open search"]`; screenshots `search-home-default-1280.png`, `search-home-default-390.png`.
- **Impact** — Every shopper on this store gets a header carrying cart and account only, on every route and at every width. Discovery is reduced to browsing even though the connector implements autocomplete and term search, and a hand-typed `/products?search=mug` returns results.
- **Fix** — Ship search on by default for static-store connectors, or derive the flag from whether the active connector exposes autocomplete, then gate the trigger on a value the connector controls. Keep the trigger inside the existing header action group so desktop shows it immediately and mobile reaches it in one tap.
- **Rule** — 5 Permanent UX rules > Global navigation > "Make search immediately visible on desktop and reachable in one tap on mobile". **Verified** — browser.

#### UX-012 · Tablet widths lose the header menu
- **Evidence** — `src/lib/components/nav/nav.svelte:198` "class="md:hidden""; `src/lib/components/nav/nav.svelte:233` "class="md:hidden""; `src/lib/components/nav/main-nav.svelte:47` "<div class="ml-6 hidden items-center space-x-6 lg:flex">"; `src/lib/components/nav/nav.svelte:244` "{#if navModule.megaMenuPluginActive}"; screenshots `header-nav-r4-default-768.png`, `header-nav-r4-plp-768-crop.png`.
- **Impact** — Between 768px and 1023px the header holds only the wordmark, cart and account. The menu button is hidden from 768px up, the inline links appear only from 1024px up, and the category row renders only when the mega-menu plugin is active, which it is not on this store. An iPad shopper has no way to reach a category, the listing or the home link from the header.
- **Fix** — Make the two breakpoints agree, either by raising the menu button to `lg:hidden` or by dropping the inline links to `md:flex`. Better, render a single category row from `md` up using the existing mega-menu markup with a flat fallback, and keep the existing ghost icon button below that breakpoint.
- **Rule** — 5 Permanent UX rules > Global navigation > "Keep the desktop header to a compact utility row plus a clearly organised category row". **Verified** — two reviewers.

#### UX-006 · Header action targets are 20px tall
- **Evidence** — `src/lib/components/nav/cart-sidebar.svelte:98` "class="flex rounded-full px-2""; `src/lib/components/nav/ms-search.svelte:61` "class="ed-search-trigger flex rounded-full px-2""; `src/lib/components/nav/nav.svelte:256` "class="ed-action flex items-center justify-center rounded-full px-2 ...""; `src/lib/components/nav/nav.svelte:286` "<UserCircle class="h-5 w-5" />"; screenshots `header-nav-r4-actions-default-390.png`, `a11y-w-header-targets-390.png`.
- **Impact** — Measured at 390px the cart hit box is 36 by 20 pixels and the account icon 20 by 20, far below the 44 pixel mobile minimum. These are the two highest-intent controls in the header, thumb taps miss them repeatedly, and the search trigger shares the same markup.
- **Fix** — Route every header action through `Button variant="ghost" size="icon"` from `src/lib/components/ui/button`, which is already 36 by 36, plus `max-sm:h-11 max-sm:w-11` for the mobile target. Padding alone will not do it, since `p-2.5` around a 20px glyph reaches only 40px.
- **Rule** — 4 Implementation architecture > Density rules > "Mobile interactive controls are normally at least 44px high"; 7 Accessibility and performance > "Pointer targets meet WCAG minimums". **Verified** — two reviewers.

#### UX-013 · Mobile menu drawer is not an accessible dialog
- **Evidence** — `src/lib/components/nav/nav.svelte:299` "<aside ... class="fixed inset-0 z-[100] flex overflow-hidden bg-transparent font-sans">"; `src/lib/components/nav/nav.svelte:301` "role="button" tabindex="0" aria-label="Close sidebar""; `src/lib/actions/dialog.ts:3`; `src/lib/components/nav/cart-sidebar.svelte:132` "role="dialog" aria-modal="true" ... use:dialog={onClose}"; screenshots `a11y-w-navdrawer-390.png`, `header-nav-r4-drawer-default-390.png`.
- **Impact** — On open the drawer has no role, no `aria-modal` and no accessible name, focus stays on the trigger, and the first three tab presses walk the header behind it. Escape leaves it open, the page scrolls underneath, closing drops focus to `body`, and the full-viewport backdrop announces itself as a button, so keyboard and screen-reader users are stranded in the only mobile navigation there is.
- **Fix** — Add `role="dialog"`, `aria-modal="true"`, `tabindex="-1"`, `aria-labelledby` and `use:dialog` to the aside, exactly as the cart drawer does. Make the backdrop a non-focusable `aria-hidden` div with only a click handler, and lock background scroll with a shared scroll lock while the drawer is open.
- **Rule** — 7 Accessibility and performance > "Visible keyboard focus, logical focus order, dialog focus trapping, Escape-to-close". **Verified** — two reviewers.

### Search

#### UX-001 · Pressing Enter in the search box lands on a 404

## Design plan

Scope: the default theme. Token work lands in `src/app.css` under `:root` and `[data-theme='default']` only. Every shared file named below is flagged as shared; the rule that keeps it safe is stated with it.

### Foundation slice

Nothing in a page slice may add a colour, radius, duration or z-index that is not defined here first.

#### 1. `src/app.css` — `:root` (additive only)

`:root` is also the fallback palette other themes inherit (UX-338), so **no existing `:root` value is re-valued here**. Only new names are added; they render nothing until a component opts in.

| Token | Value | Forced by |
| :-- | :-- | :-- |
| `--warning` / `--warning-foreground` | neutral amber + white | UX-263, UX-327, UX-096 |
| `--primary-hover` | `hsl(var(--primary))` darkened one step | UX-121, UX-261, UX-014 |
| `--border-strong` | ≥3:1 vs `--background` | UX-099 |
| `--motion-fast` / `--motion-panel` / `--motion-ease` | `140ms` / `200ms` / the value currently sitting dead in `--ease` | UX-286, UX-042, UX-113, UX-267, UX-306, UX-411, UX-427 |
| `--z-sticky/-overlay/-drawer/-modal/-popover/-toast/-skip` | `30/40/50/60/70/80/90` | UX-340, UX-117, UX-236, UX-201, UX-105, UX-101, UX-442 |

Deletions from `:root`, all zero-consumer, all additive-by-removal: `--shadow-default`, `--container-width`, `--transition-duration`, `--ease` (superseded), `--heading-font`, plus `src/routes/styles.css` and `.inter-pt` (UX-483, UX-110).

#### 2. `src/app.css` — `[data-theme='default']` (alters existing rendering)

- Declare the surface quartet the block currently inherits as grey #EEE on a white canvas: `--card: 0 0% 100%`, `--card-foreground: 222 47% 11%`, `--popover`, `--popover-foreground`. Every `bg-card` surface on the default theme changes appearance — that is the fix (UX-228, UX-374).
- Raise `--input` from `214 32% 91%` (1.13:1) to ≥3:1; keep `--border` as the soft separator but lift it off 1.13:1 (UX-099).
- Re-declare `--success` locally: white on the inherited `142 65% 36%` measures 3.73:1 and fails AA on the discount badge and coupon row (UX-263).
- Declare `--warning` / `--warning-foreground` / `--primary-hover` / `--border-strong` with the theme's own values.
- Give `--ring` a value of its own rather than a copy of `--primary`, so decoupling brand from focus cannot silently break focus (UX-287, UX-342).

Fold the `--ed-*` vocabulary into the semantic set — `--ed-canvas`→`--background`, `--ed-surface`→`--card`, `--ed-ink`→`--foreground`, `--ed-soft`→`--muted-foreground`, `--ed-line`→`--border`, `--ed-line-strong`→`--border-strong`, `--ed-radius`→`--radius`, `--ed-display`→`--font-heading`, `--ed-body`→`--font-body` (UX-014, UX-121, UX-220). ## What could not be verified

The backend and the demo catalogue put the following out of reach of a browser check. Each was
audited from code instead, and the findings say so.

- **Everything behind a sign-in.** The backend has no accounts and authentication throws a not-supported error, so the account area, order history, wishlist, saved addresses, the signup and password modals, and the logged-in checkout path were read rather than run.
- **Search as a shopper meets it.** The shipped store configuration disables the search plugin, so the trigger never renders. The panel was exercised by rewriting that flag in the served document, which shows the component code but not a configuration a merchant can currently produce.
- **Product media.** The three demo products carry no images, so the gallery, thumbnail rail, zoom, video handling and the image preload path never mounted.
- **Anything a plugin gates.** Coupons, wishlist, reviews, the newsletter, social sharing, the chat launchers and the trust badges are all inactive in this store, and the repository was read-only during the audit, so their markup was judged from source.
- **Anything a larger catalogue would show.** Pagination beyond one page and its fifty-page cap, facet counts, zero-result facet values, sorting, and category hierarchy never activated with three products and no categories.
- **Merchant-authored content.** The store serves no page blocks, banners, blog posts or content pages, so the block renderers were verified against the compiler and the source.

  serves the legal pages, and the homepage hero is a hand-written server-rendered image that already
  carries `fetchpriority="high"`. No defect to fix.
- **`f85ee01`** fixes thumbnails freezing on a variant switch, caused by `const` where runes mode
  needs `$derived`. jws's own message notes the kitcommerce-core copy is correct and only their
  vendored one was wrong. This repo's copy descends from the correct one.
- **`86de2ac`, `912a3e3`** fix 500s on `/collections` and `/vendors` from filter singletons that
  were never set. Both routes return 200 here at every width in the sweep.
- **`41c00e1`** collapses two mounted search components into one. This nav mounts one.
- **`cb6bd34`** as a mechanism patches the core package's source from a vite plugin, with anchors
  that fail the build if core moves the code. That trade is defensible for one storefront pinned to
  one core version. It is not for a template that ships against twenty-six backends and a range of
  core versions, where a build that breaks on a dependency bump is the worse failure.

### Known, deliberately not fixed

- **The account-area guard accepts a stale session.** The core guard checks only that a
  `connect.sid` cookie exists, so an expired one passes and the pages behind it fail individually.
  jws validates the session in the layout load against `/api/users/me`. That exact fix is unsafe
  here: this app has no `/api` routes, so the call would 404, and a 404 is one of the statuses jws
  treats as a dead session — every signed-in shopper would be logged out. The service-layer
  alternative is no better, because the GoCommerce connector's `getMe` reads the token from
  `document.cookie` and so returns null for every server-side call. A correct fix needs to know how
  each connector represents a session on the server, which is design work rather than a port, and it
  cannot be verified against a store with no accounts.
- **Two homepage reads still repeat.** The 200-product list and the flat category tree are each
  fetched twice, sequentially, so the in-flight dedupe cannot join them. Collapsing them needs a
  short cache with a time to live, which that module rejects on purpose: a cache can serve stale
  data and an in-flight join cannot.
